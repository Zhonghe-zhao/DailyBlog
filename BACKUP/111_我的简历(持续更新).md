### MemoBridge｜本地知识理解与状态交付工作台｜个人项目　`2026.01—至今`

面向长期学习中资料分散、思考状态难以延续以及切换 AI 会话需要重复交代上下文的问题，以长期主题和持续推进问题组织工作边界，将资料事实、AI 建议与用户确认状态分离，形成从资料捕获、证据召回、AI 辅助到理解确认及跨会话交付的闭环。

- 设计文本、链接、附件及文件夹的统一捕获管线，将原始文件身份 `Asset` 与可参与探究的业务资料 `SourceItem` 分离；通过内容去重、批次幂等键和事务化 Promote，保证并发重试下同一 Capture 只生成一份正式资料，并支持原子创建推进线及资料关系。
- 针对资料措辞与用户查询不一致导致的漏召回，基于 PostgreSQL `pg_trgm`、pgvector 与本地 bge-m3 构建词法和向量双路召回，通过确定性切片、内容 Hash 失效和 RRF 融合异构排名；在 12 条人工查询集上将 Recall@10 从 29.17% 提升至 68.06%、MRR 从 21.88% 提升至 32.62%，并在向量服务异常时降级保留非向量结果。
- 设计受控 RAG 问答链路，将用户主动组织的工作资料与主题知识库动态召回的精确片段结合，提供仅资料、协作回答和开放探索三种证据边界；模型返回后由服务端根据证据白名单校验资料 ID、引用原文及来源通道，过滤越界或伪造引用，并显式标记模型知识使用。
- 将模型交互持久化为有状态 Turn，通过 `conversation_id + client_request_id` 实现重试幂等，记录执行状态、Provider、模型、Token、延迟及上下文/检索快照；提供无模型调用的上下文预览与问题级诊断，并在请求取消或模型失败后可靠收口状态。
- 设计面向网页版大模型的 Composite Handoff，以当前主题的确认理解、未决问题和下一步作为权威状态，再从关联主题中混合召回相关开发记录和代码证据，经去重与上下文预算裁剪后生成 Markdown/JSON，使新 AI 会话能够恢复任务断点；已通过 DeepSeek 网页版验证恢复效果。

### TaskPulse｜可靠异步任务调度与执行引擎｜个人项目　`2026.05—至今`

针对长耗时任务在业务进程内执行时难以追踪、服务重启后丢失及重复执行难以收敛的问题，设计以 MySQL 为状态真相源、控制面与业务 Worker 分离的可靠异步任务运行时。

- 将任务状态、执行事件和重试信息持久化，通过 MySQL 事务与 `SELECT ... FOR UPDATE SKIP LOCKED` 实现多 Worker 并发领取，使任务能够水平消费，并保证领取结果与审计事件原子一致。
- 设计基于租约的执行权管理机制，由 Worker 心跳续租，租约过期后恢复任务，并通过 Lease Token 与 Version Fencing 拒绝旧 Worker 的延迟写回；正常停机时主动 Release，缩短任务交接时间且不消耗业务重试预算。
- 区分控制面网络重试与业务执行重试，结合错误分类、指数退避、重试预算、执行超时和取消机制处理外部服务故障；对终态提交提供幂等重放，并明确业务侧仍需处理 At-least-once 语义下的重复执行。
- 抽象 Workflow/Executor 与 Go Worker Runtime，统一封装任务领取、续租、进度、完成、失败及优雅退出；接入 MemoBridge 的语义档案和向量索引任务，并通过供应商异常、Worker 崩溃、优雅交接及终态响应丢失实验验证恢复能力。
