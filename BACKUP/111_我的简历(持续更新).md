## 项目经历

### MemoBridge｜本地知识理解与交付工作台｜个人项目  `2026.01-至今`

MemoBridge是面向长期学习中资料分散、思考过程难以延续以及切换 AI 会话需要重复交代上下文的问题，构建从文本、链接和文件捕获，到资料整理、问题探究、用户确认理解，再到 Obsidian 归档和 AI Context Pack 交付的本地知识工作台。

- 针对资料措辞与用户查询表达不一致、单一检索通道容易漏召回的问题，基于 PostgreSQL pg_trgm 与 pgvector 构建词法、语义档案、向量片段和已确认关系的混合召回链路，采用确定性切片、本地 bge-m3 生成向量并通过 RRF 融合异构排名；在 12 条人工查询中将 Recall@10 从 29.17% 提升至 68.06%，MRR 从 21.88% 提升至 32.62%，并支持向量服务失败时降级保留非向量结果。
- 面向持续研究问题构建受控 RAG，将用户主动组织的资料、已确认理解与同一主题知识库的动态召回证据结合，设计仅资料、协作回答和开放探索三种证据边界；模型返回后由服务端校验引用资料 ID 与原文片段，过滤越界或伪造引用，模型返回后由服务端根据证据白名单校验引用资料 ID、原文片段与来源通道，仅资料模式在证据不足时拒绝生成确定性结论，并显式标记模型知识使用，降低外部知识被伪装成本地证据的风险。
- 设计面向网页版大模型的组合交付包：以当前主题的确认理解、未决问题和下一步作为权威状态，再从关联主题中混合召回相关开发记录和代码证据，经去重及上下文预算裁剪后生成 Markdown/JSON，使新 AI 会话能够恢复任务断点；已使用 DeepSeek 网页版验证恢复效果。

### TaskPulse｜通用可靠异步任务执行引擎 | 个人项目 `2026-05-至今`

面向秒级至分钟级、需要状态追踪与故障恢复的后台任务，实现以 MySQL 为状态真相源、由独立 Worker 承载业务逻辑的可靠异步任务运行时。

- 基于 MySQL 事务与 SELECT ... FOR UPDATE SKIP LOCKED 实现多 Worker 并发 Claim，将任务领取、租约建立及执行事件原子提交，避免重复领取以及任务状态与审计事件不一致。                                              
- 设计 Lease、Heartbeat、Lease Token 与 Version Fencing 执行权协议；Worker 崩溃后允许其他实例在租约过期后恢复任务，并拒绝旧 Worker 的进度和终态写回；正常退出时主动 Release，缩短交接时间且不消耗重试预算。
- 针对“业务写回成功但 Complete 响应丢失”的不确定结果，实现相同 Fencing 凭证下的终态幂等重放，并由业务侧结合资源 ID、内容 Hash 与版本信息完成幂等写回；明确系统提供 At-least-once 执行尝试而非虚构 Exactly-once。
- 抽象 Workflow/Executor 与 Go Worker Runtime，统一封装领取、续租、重试、进度上报、终态提交和优雅退出；通过 MemoBridge 的真实 DeepSeek SemanticProfile 与 bge-m3 Embedding 任务，验证 Provider 故障重试、Worker 交接、进程崩溃恢复及 Complete 重放。
